# U-Ray vs NumPy: воспроизводимые бенчмарки

Этот набор сравнивает встроенный `native` backend U-Ray с NumPy на одной
машине и на одинаковых входных данных. Он измеряет отдельные численные ядра
и полноценные ML-процессы; результаты разных задач нельзя сводить к заявлению
«U-Ray быстрее NumPy вообще».

## Запуск

Из корня репозитория:

```bash
python3 benchmarks/benchmark_matmul.py
python3 benchmarks/benchmark_conv2d.py
python3 benchmarks/benchmark_transformer.py
python3 examples/download_mnist.py
python3 benchmarks/benchmark_mnist.py --data-dir examples/data/mnist
python3 benchmarks/benchmark_cnn.py --data-dir examples/data/mnist
```

MNIST-запуски дольше. Для MLP можно ограничить выборку через
`--train-samples`/`--test-samples` и задать `--epochs`; для CNN доступны
`--full`, те же лимиты выборки и `--epochs`. У обоих ML-сценариев есть
`--iterations` и `--warmups`; дополнительные повторы повышают устойчивость
результата, но увеличивают время обучения пропорционально. Чтение датасета и
генерация синтетических входов не входят в измеряемый интервал.

## Что измеряется

| Сценарий | Задача и контроль качества |
| --- | --- |
| `benchmark_matmul.py` | `Tensor.matmul` для квадратных и типичных dense-layer матриц; входные Tensor создаются до таймера, сравнивается весь выход |
| `benchmark_conv2d.py` | Conv2D forward + backward на входах 28×28; сравниваются все выходы и градиенты |
| `benchmark_transformer.py` | Обучение и проверка Transformer на синтетической регрессии; проверяется снижение MSE на отложенных данных |
| `benchmark_mnist.py` | Один цикл обучения и оценки MLP на полных MNIST train/test |
| `benchmark_cnn.py` | Один цикл обучения и оценки CNN; по умолчанию 10 000 train/test примеров, `--full` использует весь набор |

У MLP и CNN по умолчанию одна измеряемая итерация и нет дополнительного
прогрева: это полные циклы обучения, поэтому повторы дорогие. Для проверки
разброса укажите, например, `--iterations 3`.

## Правила сравнения

- NumPy ограничен одним потоком по умолчанию — как и нынешние native CPU-ядра.
  Для отдельного эксперимента число потоков можно задать до запуска, например
  `URAY_BENCH_NUMPY_THREADS=4`; такие результаты нельзя напрямую смешивать с
  однопоточными.
- Пары запусков идут вперемешку; порядок `numpy`/`native` псевдослучайный и
  воспроизводимый по `--seed`.
- В `benchmark_matmul.py` размеры задаются как `M×K×N`, например
  `--shapes 128x784x64,128x64x10`; создание входных Tensor не входит в
  замер. По умолчанию проверяются как квадратные матрицы, так и формы,
  типичные для полносвязных слоёв.
- Измеряемое время — медиана, разброс — MAD (медианное абсолютное отклонение).
  Для матричного умножения и Conv2D полные результаты проверяются на численную
  близость; ML-сценарии отдельно проверяют качество на test/held-out данных.
- `native/NumPy < 1` означает, что native быстрее в этом конкретном сценарии;
  `> 1` — что медленнее. Это не прогноз для другого процессора, числа потоков
  или размера задачи.

GitHub Actions запускает корректностные тесты, но не фиксирует время
бенчмарков: общие CI-машины и частотное масштабирование CPU делают такие
пороговые проверки шумными.
